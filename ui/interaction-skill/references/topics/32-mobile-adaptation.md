# 修好已有页面的手机端适配

> 按需参考 · 主题 32。处理电脑端已经可用、手机端却拥挤、溢出或难以操作的页面。只修改当前问题，不把适配变成整站换风格。

## 先定位问题，再改布局

读取目标页面的容器、布局、图片、文字和相关弹层。用同一份内容和素材建立桌面与窄屏基线，记录具体撑宽或遮挡的元素；只有截图时先提出待核实的位置，不声称找到代码根因。

按内容开始失效的宽度决定断点，沿用项目已有规范。360、390、430 像素可以作为手机检查样本，还需检查断点前后、中间宽度及已有桌面布局；这些数字不是必须采用的 CSS 断点。只有原需求包含平板、横屏等设备时再扩展对应场景。

## 把每一种问题交给对应处理

| 观察到的问题 | 优先检查与修改 | 不用什么掩盖 |
|---|---|---|
| 侧栏挤占主要内容 | 按任务保留搜索、筛选、内容和主要操作；把次要导航改成可访问的展开入口 | 整个桌面页面等比缩小 |
| 卡片太窄、列数太多 | 依据卡片最小可读宽度与容器空间调整列数、间距和排列 | 只缩小字号以硬塞多列 |
| 页面横向滚动 | 检查固定宽度、最小宽度、不可换行内容、外边距和定位偏移；逐个确认溢出来源 | 给根节点加 `overflow-x: hidden` 裁掉内容 |
| 图片主体被裁掉 | 保持比例，决定完整展示还是允许裁切，再调展示区域与主体位置；必要时增加卡片高度 | 拉伸图片或默默换一张素材 |
| 标题被切、标签拥挤 | 允许自然换行，取消不合适的固定高度，让后续内容参与正常排版；长标识单独设置换行策略 | 给所有内容设固定行数或缩到难读 |
| hover 才出现关键操作 | 提供直接可见、可点的按钮或菜单，检查命中区域与相邻间距 | 要求触屏用户猜长按或先触摸一次才能发现 |

局部表格、代码块或时间轴有合理横向浏览需求时，可以提供有边界的区域滚动和提示；不要把“任何滚动都禁止”当成适配目标。图片的替代文本、真实标题和按钮语义不能在视觉修改时丢失。

## 输入、弹层和返回仍要能用

- 筛选或搜索时保留当前输入和选择；尺寸变化不应触发重置、重复请求或丢失滚动位置。
- 弹层按其实际语义处理焦点和关闭，内容超过高度时可滚动。软键盘出现后仍能看到正在输入的字段和必要操作；固定底栏不盖住正文尾部。
- 收起导航不能让它在不可见时仍参与键盘遍历。关闭后回到合理触发位置；模态与非模态的处理区别见 [02 · 浮层与通知](02-overlay-components.md)。
- 触屏页面保留正常滚动，只在确需拖动的局部协调手势。减少动态效果时仍能打开菜单、完成筛选与返回。

## 可直接交给 AI 的请求

> 请检查【页面】的手机端适配，先指出具体哪个元素撑宽、遮挡或挤占空间，再修改对应布局。保留现有配色、图片、文案、功能及已经正常的电脑端。按主任务调整导航、卡片列数、图片裁切和标题换行，不整页缩小，不用隐藏溢出盖住问题。触屏操作不能依赖 hover。完成后沿【搜索 → 筛选 → 详情 → 返回】检查不同宽度、长标题、图片主体、弹层与键盘，列出实际操作过的结果和仍需真机检查的部分。

## 验收要看同一份内容

1. 在修改前相同的内容与宽度下复现原问题，再检查修复结果；换成长标题、空列表及图片加载失败状态，而不是只改尺寸标签。
2. 实际点击搜索、分类、卡片和返回，验证改变的是对应内容，且状态、焦点和滚动位置合理。
3. 检查断点两侧与原桌面尺寸，确认此次局部适配没有破坏已有正常布局。
4. 报告区分浏览器模拟视口、键盘操作、触摸模拟和手机真机测试。视频中的演示、截图与构建成功都不能替代真机结论。
