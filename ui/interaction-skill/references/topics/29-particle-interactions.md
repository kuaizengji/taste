# 粒子交互

> 按需参考 · 主题 29《粒子交互》。粒子应该解释一个真实动作或状态变化，不是把所有元素散成背景。一次只选一种模式，并保留可读的 HTML 内容和普通操作入口。

## 1. 三种模式与适用问题

| 模式 | 输入与结果 | 适合 |
|---|---|---|
| 局部拨散归位 | 指针接近，附近点让开；离开后回到各自原位 | 首屏提示可探索、突出一个局部对象 |
| 同点变形 | 同一批有稳定 ID 的点切换到已准备的目标形状 | 作品类别、品牌状态或筛选结果的可视切换 |
| 音频响应 | 播放中的频率数据改变轮廓或细节，暂停后安静 | 音乐、播客或声音作品的封面入口 |

局部拨散不是全屏漂移，变形不是两张图片淡入淡出，音频响应也不应成为唯一导航。数据密集页面、表单和关键提示应使用普通布局。它和 [12《图片交互》](./12-image-interactions.md) 的区别是：12 讨论图片的查看与揭示，29 讨论点的身份、目标和回归；它也不替代 [14《滚动驱动官网》](./14-scroll-driven-site.md) 的页面编排或 [17《空间卡片布局》](./17-spatial-card-layouts.md) 的卡片排列。不要只换一张图片或颜色。

## 2. 状态、取消与输入

把视觉状态写成 `idle`、`active`、`settling`、`stable`、`cancelled`，并让业务状态独立存在。拨散需要记录每个点的原位，指针离开、失焦或 `pointercancel` 后回归；变形要有“目标选中、过渡、停稳、返回”的路径，重复点击从当前进度接管；音频只在真实播放时更新，暂停、结束、页面隐藏时停止或降级。

鼠标移动不能是唯一操作：用按钮、键盘选择或明确的播放控件提供同一结果。减少动态效果时保留静态轮廓和目标文字。点数、更新频率和画布尺寸随设备能力调整，禁止无条件持续渲染；错误音频、失效图片和不支持 WebGL 时仍显示可读内容。

## 3. 资产与技术选择

图片可用来采样位置、颜色和透明轮廓，但不是把一张静态图伪装成可交互页面。变形的每个点要有稳定 ID 和目标数组，音频分析需要用户明确播放并用 `AnalyserNode` 获取时域或频域数据。少量点可用 Canvas 或 DOM；大量点再考虑 WebGL、BufferGeometry 或自定义材质。Shader 不是必选，也不能从一张图片承诺真实 3D；先确认项目已有渲染器、回退方案和素材授权。

## 4. 可以这样跟 AI 说

> 先阅读当前页面的真实内容和交互入口，只实现一种粒子模式。若选拨散：为每个点保留原位，指针附近才受力，离开、失焦或取消后缓动归位；若选变形：用同一批稳定 ID 点切换两个真实目标，并保留按钮、键盘和静态列表；若选音频：只在用户播放时读取分析数据，暂停和结束后停止更新。请把粒子当作视觉层，标题、链接和选择控件用可访问 HTML；根据窄屏和减少动态偏好提供静态回退。不要加入默认人物、配色、音乐或“全功能 Shader/3D”承诺。

## 5. 验收

- 拨散只影响邻近点并能回到原位；变形不出现整图淡入假象；音频暂停后粒子不会继续飘动。
- 从移动、点击、播放、离开、取消、重复触发和页面隐藏恢复时，状态不跳回旧起点，不出现多个更新循环。
- 关键内容可用键盘和普通 HTML 入口访问；窄屏、图片或音频失败、WebGL 不可用时仍能完成任务。
- 记录实际运行、视觉检查和用户确认的边界，不把视频中的效果写成已部署或已完整测试。

## 6. 官方文档

- [MDN Pointer events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)：统一指针输入并处理 `pointercancel`。
- [MDN AnalyserNode](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode)：核对实时频率或时域分析入口。
- [MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)：安排可暂停的帧更新。
- [Three.js BufferGeometry](https://threejs.org/docs/pages/BufferGeometry)：核对点属性、颜色与可复用缓冲。
