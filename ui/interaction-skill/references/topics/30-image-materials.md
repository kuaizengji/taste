# 图片材质交互

> 按需参考 · 主题 30《图片材质交互》。它把图片拆成光照、透镜或织带等“同一素材的状态变化”，用来解释作品或引导查看；先确认图片本身值得交互，再选择一个效果。

## 1. 模式与真实边界

| 模式 | 适用输入 | 必须说清楚 |
|---|---|---|
| 重新打光 | 指针或滑块改变光照方向 | 可用深度近似和法线制造明暗；仍是一张平面图，没有真实背面 |
| 玻璃透镜 | 指针经过或拖动镜片 | 同一图像的灰度、颜色和局部 UV 扰动；不是另一张照片，也不是可任意旋转的玻璃物体 |
| 图片织带 | 拖动展开或收回 | 按同一素材的 UV/条带切分，拖回后还原；不是把图片换成无关纹理 |

选择一个能帮助访客看懂作品的局部结果，不要三种一起堆。[12《图片交互》](./12-image-interactions.md) 覆盖通用查看、缩放和揭示；30 新增的是材质近似、同图连续性和资产边界，所以不能只把旧交互换成玻璃颜色。它不负责 [14《滚动驱动官网》](./14-scroll-driven-site.md) 的整页编排，也不替 [17《空间卡片布局》](./17-spatial-card-layouts.md) 安排内容。若图片只是装饰或页面需要快速读文字，静态图片更合适。

## 2. 状态、输入与退出

定义 `rest`、`active`、`settling`、`held`、`returning`。指针进入、拖动或聚焦后才改变，移动到目标后短暂停稳；离开、松手、Esc、取消或切换页面时从当前进度回到可读的原图状态。织带必须有明确的拖动边界和回收动作，触摸设备提供按钮或滑块，不依赖 hover。材质层不能遮住标题、链接和替代文本，图片失败时显示普通内容。

## 3. 资产与技术选择

重新打光可准备一张基础图及可选的深度、法线或遮罩图，但近似深度只用于视觉光照，不能承诺精确三维重建、头发遮挡或背面视图。透镜使用同一张颜色图，外部状态和镜内状态要有明确对照；织带的每条片段要保留原图对应 UV，避免拼回时出现错位和接缝。CSS 变换已足够时不必上 WebGL；需要大量像素或 UV 变形再考虑 Canvas/WebGL/现有渲染器。不要把 Shader、3D 模型或生成图当作必然结果，也不要引入未授权的图片、字体和纹理。

## 4. 可以这样跟 AI 说

> 先检查当前页面的真实图片、版权来源、响应式布局和已有组件，只实现一种图片材质交互。保留图片的主体、文字和链接：光照模式只改变明暗，不生成背面；透镜模式只在明确区域显示同图的颜色或轻微折射；织带模式按原图连续切分，拖动可中途取消并回到原图。请同时做键盘/触摸替代入口、指针离开和 `pointercancel` 回收、减少动态效果分支、加载失败回退和移动端静态方案。不要默认换色、换人物或把概念图写成完整 3D 实现。

## 5. 验收

- 输入前图片保持原状态，输入中变化跟随同一素材，停稳后可读；离开、松手、Esc、取消和重复触发都能回收。
- 透镜内外、条带拼接或光照变化没有明显错图、跳变和遮挡；图片说明、链接和键盘焦点仍可访问。
- 调整宽度、触摸操作、图片加载失败和减少动态偏好后，页面仍能完成查看任务；不把“看起来像 3D”写成真实三维或已上线证据。

## 6. 官方文档

- [MDN Pointer events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)：处理鼠标、触摸、触笔及取消。
- [MDN WebGL API](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API)：核对像素级渲染能力与降级边界。
- [Three.js Texture](https://threejs.org/docs/pages/Texture.html)：核对纹理尺寸、颜色空间和 UV 相关设置。
- [Three.js ShaderMaterial](https://threejs.org/docs/pages/ShaderMaterial.html)：仅在确有自定义 GPU 材质需求时查阅。
